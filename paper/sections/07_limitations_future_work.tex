\section{Limitations and Future Work}

The most important limitation is event availability. NOAA Storm Events records
are official and source-verified, but the public detail files do not provide
machine-readable publication timestamps. The event-aware component therefore
uses event start time as the availability proxy. This makes the reported
event-aware results retrospective sensitivity results rather than strict
operational nowcasts. A production deployment would require sources with
auditable issue times, such as alert archives, smoke products, or an HMS cache
with verified timestamps.

The second limitation is external validation. The experiment evaluates one
carefully audited setting: Los Angeles County PM2.5 from 2019--2024. This is
appropriate for an initial site-specific evaluation, but it does not establish
geographic generalization. Future work should repeat the same protocol on
another U.S. county or city with different meteorology, emissions, and event
profiles.

The third limitation concerns model integration. Event-TimeRAF currently uses
retrieved trajectories and event context as feature-level evidence, a lightweight
validation-selected drift gate, and a frozen Chronos-Bolt evaluation. This
provides less expressive retrieval integration than a learnable
retrieval-and-prompting architecture that directly conditions the foundation
model. Future work should test a learnable retriever, richer event-type
embeddings, calibrated uncertainty estimation, and a closer adaptation of
TimeRAF-style Channel Prompting for environmental forecasting.
