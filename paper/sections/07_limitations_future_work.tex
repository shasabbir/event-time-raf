\section{Limitations and Future Work}

The most important limitation is event availability. NOAA Storm Events records
are official and source-verified, but the public detail files do not provide
machine-readable publication timestamps. The event-aware component therefore
uses event start time as the availability proxy. This makes the reported
event-aware results retrospective sensitivity results rather than strict
operational nowcasts. A production deployment would require sources with
auditable issue times, such as alert archives, smoke products, or an HMS cache
with verified timestamps.

The second limitation is external validation. The final experiment evaluates one
carefully audited setting: Los Angeles County PM2.5 from 2019--2024. This is
appropriate for a scoped Kaggle implementation, but it does not establish
geographic generalization. The faculty-quality target asks for validation on a
second dataset; for this study, that remains future work rather than a result.
A stronger version should repeat the same protocol on another U.S. county or
city with different meteorology, emissions, and event profiles.

The third limitation concerns model integration. Event-TimeRAF currently uses
retrieved trajectories and event context as feature-level evidence, with a
frozen Chronos-Bolt gate for foundation-model validation. This is weaker than a
learnable retrieval-and-prompting architecture that directly conditions the
foundation model. Future work should test a learnable retriever, richer
event-type embeddings, calibrated uncertainty estimation, and a closer
adaptation of TimeRAF-style Channel Prompting for environmental forecasting.

Finally, the present manuscript uses verified references and official data
sources only. The reference list should be expanded with additional recent
2023--2026 air-quality forecasting, time-series foundation model, retrieval, and
explainability studies before journal submission.
